你現在是本專案的「Skill Author + Frontend/Firmware Context Integrator」。
你的唯一任務是：在這個專案中，直接建立可用的 Project Skills（不是只提供建議），讓後續 agent 能穩定地做「盲人眼鏡專案前端開發」，且不誤判 firmware 能力範圍。

========================
一、目標與範圍（不可偏離）
========================
1) 你要建立的是「本專案技能」，供 Gemini 使用。
2) 技能路徑以 `.gemini/skills/` 為主，且必須可直接被讀取使用。
3) 同時建立 `.agents/skills/` 鏡像副本（相同內容），提升跨 agent 相容性。
4) 本次重點是「前端控制台 + firmware/API 對齊 + 驗證流程」。
5) 不要假設藍牙耳機音訊（A2DP/HFP）已可用；目前以 BLE 快速連線與裝置控制流程為主。
6) 所有規格判讀需對齊：
   https://github.com/YuQian081122/blind-glasses/tree/main/firmware

========================
二、硬性規則（必須遵守）
========================
A. 路徑規則
- 必須建立：
  - `.gemini/skills/blind-glasses-app-frontend/SKILL.md`
  - `.gemini/skills/blind-glasses-firmware-api-context/SKILL.md`
  - `.gemini/skills/blind-glasses-frontend-qa/SKILL.md`
- 必須同步鏡像到：
  - `.agents/skills/blind-glasses-app-frontend/SKILL.md`
  - `.agents/skills/blind-glasses-firmware-api-context/SKILL.md`
  - `.agents/skills/blind-glasses-frontend-qa/SKILL.md`
- 若目錄不存在，請自動建立。

B. 內容規則
- 每個 SKILL.md 必須包含 YAML frontmatter：
  - `name`
  - `description`
- `name` 用小寫與連字號，且固定如下：
  - `blind-glasses-app-frontend`
  - `blind-glasses-firmware-api-context`
  - `blind-glasses-frontend-qa`
- `description` 必須同時包含：
  1. WHAT（做什麼）
  2. WHEN（何時觸發）
- 嚴格避免模糊字眼（例如「可能可以」「大概」「也許」），改成可執行規則。

C. 防誤判規則
- 不得杜撰不存在 API、欄位、或 BLE 指令。
- 不得把 BLE 快速連線誤寫成藍牙耳機音訊串流能力。
- 不得直接修改 firmware 協定定義（除非使用者明確要求）。
- 遇到資訊不足時，必須先要求讀取本地程式碼並標記「待確認」。

D. 風格規則
- 指令型寫法、清楚步驟、可直接執行。
- 術語一致：
  - 固定使用「BLE 快速連線」
  - 固定使用「模式切換（general / light / item_search）」
  - 固定使用「裝置狀態」
- 路徑示範使用正斜線 `/`（避免反斜線造成跨平台混淆）。

========================
三、三個技能的詳細需求
========================

Skill 1: blind-glasses-app-frontend
- `.gemini/skills/blind-glasses-app-frontend/SKILL.md`
- `.agents/skills/blind-glasses-app-frontend/SKILL.md`

- `.agents/skills/blind-glasses-firmware-api-context/SKILL.md`
- 目的：提供前端可依賴的 firmware/API 事實來源與查證流程。
- 必含：Source of Truth、Capability Matrix、Verification Procedure、Ambiguity Handling、Safe Assumptions、Terminology Lock。

Skill 3: blind-glasses-frontend-qa
- `.gemini/skills/blind-glasses-frontend-qa/SKILL.md`
- `.agents/skills/blind-glasses-frontend-qa/SKILL.md`
- 目的：規範前端驗證與回歸流程，確保每次變更可測可交付。
- 必含：Test Checklist、Regression Focus、Observability、Done Criteria、Report Format。
